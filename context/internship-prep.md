## Projects to Prioritize

### What makes a project resume-worthy
- Solves a real problem (even a small one)
- Has a working, deployed version (not just code on GitHub)
- Uses at least one real technology you had to learn (API, database, framework)
- You can explain every line in an interview

### Project tiers (pick from these)

**Tier 1 — Build first (high signal, manageable scope)**
- CLI tool that automates something you actually do
- REST API with a database (even a simple CRUD app with a clear use case)
- Web scraper or data pipeline with a real output (report, dashboard, file)
- Discord/Telegram bot with real utility

**Tier 2 — Build second (stronger signal, more complexity)**
- Full-stack web app (simple frontend + your own backend)
- Something that integrates 2+ external APIs
- A tool that other people actually use (even a few)

**Tier 3 — Avoid for now**
- Todo apps, weather apps, calculator clones — overdone, no signal
- Projects that are just tutorial code with your name on them
- Anything so complex it never ships

### What to show on GitHub
- Pinned repos only for your best 2–3 projects
- Each repo needs: clear README, what it does, how to run it, tech used
- Commit history that looks real (not one giant commit)
- No empty repos, no forks with no changes

## What Recruiters Look for (Non-T20 School)

### The honest reality
At a non-flagship school, your resume gets less benefit of the doubt.
You need to *show* competence instead of implying it via school name.
The bar is: can you demonstrate you've built real things and can think like an engineer?

### What moves the needle

**Projects > GPA (after ~3.5)**
A deployed project with a good README signals more than a 3.9 with no code online.

**GitHub activity matters**
Recruiters and engineers do look. Green squares + real repos = credibility.
Empty GitHub = missed opportunity.

**Resume clarity**
- Bullet points: action verb + what you built + what it does + tech used
- Bad: "Built a web app using React"
- Good: "Built a task scheduling web app with React and Node.js, used by 3 study groups to coordinate weekly deadlines"

**Relevant coursework + DSA**
List DS&A, OS, and any systems courses. They signal you can handle technical interviews.
LeetCode easy/medium fluency is the floor for phone screens.

**Fit > prestige at most companies**
Mid-size tech companies, startups, and non-FAANG firms are where most CS students land their first internship.
They care more about "can this person contribute?" than where you went to school.

### What doesn't help as much as students think
- Hackathon participation (without a strong project outcome)
- Certifications (AWS, Google) — minor signal, not a substitute for projects
- Listing every language you've touched ("Familiar with C++, Ruby, Go...")
